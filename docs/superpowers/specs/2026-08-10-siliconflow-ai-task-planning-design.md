# 硅基流动 AI 任务拆解设计

## 目标

在项目任务看板中，团队成员输入项目目标后，由硅基流动的 `Qwen/Qwen2.5-7B-Instruct` 生成结构化任务草稿；用户在页面中确认前可编辑或删除草稿，确认后才批量创建为当前项目的待办任务。

## 环境变量与安全边界

只在 `apps/api/.env` 中保存下列配置：

```dotenv
SILICONFLOW_API_KEY=
SILICONFLOW_BASE_URL=https://api.siliconflow.cn/v1
SILICONFLOW_MODEL=Qwen/Qwen2.5-7B-Instruct
```

前端不接触 Key，也不调用硅基流动。后端不记录 Authorization 请求头、Key 或模型完整原始响应。缺少 Key 时返回清晰的“AI 服务尚未配置”错误。

## 后端设计

新增独立的 `AiModule` 和 `SiliconFlowTaskPlanningService`，使用 Node 原生 `fetch` 请求 `${SILICONFLOW_BASE_URL}/chat/completions`。系统提示词限定输出纯 JSON：

```json
{
  "tasks": [
    {
      "title": "任务标题",
      "description": "交付说明",
      "priority": "low | medium | high"
    }
  ]
}
```

服务端移除可能存在的 Markdown 代码围栏并解析 JSON，随后运行时校验：任务数量为 1 至 8，标题 2 至 200 字符，说明最长 5000 字符，优先级属于既有枚举。模型返回不合规时不创建任务，返回安全的上游响应错误。

新增受 JWT 保护的接口：

- `POST /api/projects/:projectId/ai/task-drafts`：验证当前用户是项目团队成员，接收 `goal`（10 至 2000 字符），返回未持久化的 AI 草稿。
- `POST /api/projects/:projectId/tasks/batch`：验证团队成员身份，接收用户确认后的 1 至 8 个草稿，二次执行同样字段校验，在事务中批量创建任务。每个任务状态为 `todo`、负责人为 `null`。

批量创建复用 Tasks 模块的团队项目访问校验和 `TaskSummary` 输出格式；不保存 AI 对话、提示词以外的模型原始内容，也不添加数据库表。

## 前端设计

在现有 `TaskBoardPage` 的创建任务表单下新增“AI 拆解项目”面板：

1. 输入项目目标，点击“生成任务草稿”。
2. 请求成功后展示 1 至 8 条可编辑的草稿卡片，每条可修改标题、说明和优先级，也可单独移除。
3. 点击“确认创建任务”才调用批量接口；成功后将返回任务追加到待办列，并清空草稿和目标输入。
4. 生成或确认中禁用相应操作，失败时保留用户输入/草稿并显示中文错误。

不新增路由，不使用全局状态库，不做流式输出或聊天历史。

## 错误与限流

- 配置缺失：503，提示 AI 服务未配置。
- 硅基流动 401/403：502，提示 AI 服务认证失败。
- 硅基流动 429：429，提示请求过于频繁，请稍后再试。
- 上游网络错误、非 JSON 或结构不合规：502，提示 AI 服务暂时不可用。
- 非团队成员：沿用项目访问校验的 403。

## 测试

- 后端通过 Mock 全局 `fetch` 测试成功草稿解析、代码围栏解析、配置缺失、429、无效模型输出和不发送真实网络请求。
- 后端任务接口测试批量确认创建、团队权限和字段校验。
- 前端测试覆盖生成草稿、编辑/删除草稿、确认后待办列更新、生成失败保留输入，以及不把 Key 放入浏览器请求。
