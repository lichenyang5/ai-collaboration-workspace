# 任务详情编辑设计

## 目标

让团队成员能够在项目任务看板中编辑已有任务的标题、说明、优先级、负责人和截止日期；保存后，卡片在当前看板中立即反映服务端返回的最新数据。

## 范围

- 点击任务卡片中的“编辑详情”打开同页详情面板，不新增路由。
- 可编辑字段：标题、说明、优先级、负责人、截止日期。
- 状态列仍只通过现有“移动到下一状态”操作流转，不放入详情表单。
- 保留创建任务、任务移动、团队成员加载和错误提示行为。

不包含评论、附件、通知、任务删除、成员角色管理或任务筛选。

## 后端设计

新增 `PATCH /api/tasks/:taskId`。请求 DTO 对每个字段使用可选校验：标题长度 2 至 200，说明最长 5000，优先级必须为既有枚举值，截止日期为 ISO 日期，负责人 ID 为 UUID。

服务端先按任务 ID 加载任务、所属项目团队及现负责人；不存在返回 404。随后确认当前用户仍属于该团队；不属于团队返回 403。传入负责人 ID 时确认该用户属于同一团队，否则返回 400。未传负责人字段保持原值；传入 `null` 表示取消指派。保存后加载/保留负责人关联，并返回既有 `TaskSummary` 结构。

## 前端设计

`TaskBoardPage` 增加一个当前编辑任务状态。用户点击“编辑详情”后，以该任务的当前字段初始化受控表单；负责人下拉列表复用已经加载的团队成员。保存时请求新增接口，成功后按任务 ID 在对应状态列替换该卡片；失败时在详情面板显示服务端错误。取消不发送请求，也不修改看板数据。

截止日期显示和传输采用 `YYYY-MM-DD`：加载时将 API 时间字符串截取为日期部分；为空时不发送该字段；清空已有日期时发送 `null`。

## 测试与错误处理

- 后端控制器测试覆盖更新字段、更新负责人、取消负责人，以及非团队成员与非法负责人的拒绝。
- 前端测试覆盖打开详情、保存后卡片即时更新、取消不请求接口、保存失败仍保留表单内容。
- 不记录敏感信息；所有错误均显示现有 API 错误消息或简洁中文兜底文案。
