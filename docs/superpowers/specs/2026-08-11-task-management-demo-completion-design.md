# 任务管理与作品 Demo 闭环设计

## 背景

项目已经具备注册登录、团队和项目管理、成员邀请、任务创建与编辑、负责人分配、状态流转，以及 AI 任务拆解能力。下一阶段不再横向堆叠大型模块，而是补齐任务管理中的高频操作、可追溯性和演示数据，使面试官能在五分钟内看懂产品闭环，同时看到 React、NestJS、PostgreSQL 与 AI 集成的完整实现。

当前 `TaskBoardPage` 同时承担看板加载、成员加载、任务创建和编辑、状态更新、AI 草稿管理与大量渲染职责。新增功能时需要做与本阶段直接相关的组件拆分，但不进行无关重构。

## 目标

- 支持按关键词、负责人、优先级和截止状态组合查找任务。
- 在创建任务时直接设置截止日期，并明确展示临期和逾期状态。
- 允许归档已完成任务，并支持查看和恢复归档任务。
- 为任务的重要变化生成可读、可追溯的活动记录。
- 提供安全、幂等的本地 Demo 数据脚本和清晰的五分钟演示路径。
- 同步 README、运行步骤、功能截图和验证说明，使仓库本身可以作为作品交付。

## 非目标

本阶段不实现评论、附件、实时通知、成员移除、成员角色调整、团队转让、密码找回、更多 AI 能力、复杂 RBAC、生产运维平台或不可恢复的物理删除。

## 演示路径

1. 使用 Demo 负责人账号登录并进入已有团队和项目。
2. 按关键词、负责人、优先级和截止状态筛选任务。
3. 打开逾期任务，修改负责人、截止日期或其他详情。
4. 将任务推进到已完成并归档，再从归档区恢复。
5. 在活动记录中查看刚才的创建、编辑、状态和归档变化。
6. 输入一个项目目标，由 AI 生成任务草稿，编辑确认后加入待办列。

## 数据模型

### 任务归档

在 `tasks` 表和 `Task` 实体中增加可空的 `archived_at`。值为空表示活跃任务；有值表示已归档任务。归档不会改变任务原有字段，恢复时清空 `archived_at`，任务状态保持 `done`。

新增适合项目和归档状态查询的索引。数据库变更通过版本化 SQL migration 提供，现有数据库不需要重建；基础 `schema.sql` 同步更新，保证空数据库初始化与迁移后的结构一致。

### 任务活动

新增 `task_activities` 表和对应实体，字段包括：

- `id`
- `task_id`
- `actor_id`
- `event_type`
- `details` JSONB
- `created_at`

`event_type` 限定为 `created`、`updated`、`status_changed`、`assignee_changed`、`archived` 和 `restored`。`details` 只保存生成展示文案所需的前后值，例如状态、负责人公开标识、优先级和截止日期；不保存密码、Token、AI Key 或完整请求体。

任务发生多类变化时，可以在一次保存中生成多条语义明确的记录，例如同时修改负责人和截止日期。任务修改与对应活动记录在同一个数据库事务中提交。

## 截止状态语义

API 将截止日期按 UTC 日历日规范化，前后端均使用 `YYYY-MM-DD` 表示，避免浏览器时区造成日期偏移。

- `unset`：未设置截止日期。
- `overdue`：任务未完成，且截止日期早于当前 UTC 日期。
- `due_soon`：任务未完成，且截止日期处于当前 UTC 日期至未来三天的闭区间。
- `normal`：已设置日期，但不属于逾期或临期。

已完成任务不会标记为逾期或临期。

## 后端接口

### 看板筛选

扩展 `GET /api/projects/:projectId/tasks`，支持以下可选查询参数：

- `q`：对标题和描述进行大小写不敏感的包含匹配。
- `assigneeId`：团队成员 ID；`unassigned` 表示未指派。
- `priority`：`low`、`medium` 或 `high`。
- `due`：`unset`、`normal`、`due_soon` 或 `overdue`。
- `view`：`active` 或 `archived`，默认 `active`。

响应继续沿用当前分列结构，降低前端改造范围。查询参数需要 DTO 校验；负责人筛选值必须属于当前项目团队。活跃视图默认排除归档任务，归档视图只返回已归档任务。

### 创建和编辑

扩展现有任务创建 DTO，使其接受可空的 `dueDate`。现有任务编辑接口继续负责标题、说明、优先级、负责人和截止日期变更，并在事务内写入对应活动记录。

### 归档和恢复

新增 `PATCH /api/tasks/:taskId/archive`，请求体为 `{ "archived": true | false }`。

- 只有状态为 `done` 的活跃任务可以归档。
- 只有已归档任务可以恢复。
- 团队成员可以归档和恢复本团队任务；非成员返回 403。
- 重复归档或重复恢复返回 409，不静默成功。

### 活动列表

新增 `GET /api/projects/:projectId/task-activities`，验证项目访问权限后返回最新 50 条记录，按时间倒序排列。响应包含活动 ID、任务公开摘要、操作者公开摘要、事件类型、展示所需详情和发生时间，不返回敏感用户字段。

本阶段不实现活动分页 UI；50 条上限足够支撑作品演示，并避免无界查询。

## 前端设计

`TaskBoardPage` 保留路由参数、页面级加载和各区域组合职责，拆出以下单一职责组件：

- `TaskFilters`：维护搜索与组合筛选控件。
- `TaskCard`：展示任务摘要、截止状态和操作入口。
- `TaskEditor`：处理任务详情编辑。
- `TaskArchivePanel`：展示归档任务和恢复操作。
- `ActivityPanel`：展示项目活动时间线。
- `AiTaskPlanner`：封装现有 AI 目标输入、草稿编辑和确认流程。

筛选状态写入 URL 查询参数。首次加载从 URL 恢复，筛选变化以短防抖更新查询参数并重新请求看板数据；刷新或复制链接后筛选条件仍然有效。空筛选参数不写入 URL。

任务卡片显示截止日期，并根据截止状态展示“今天到期”“三天内到期”或“已逾期”等清晰标签。创建表单增加截止日期字段，与编辑表单使用同一日期格式。

归档入口只在已完成任务上出现，并在执行前要求确认。归档成功后任务从活跃看板移除并追加活动；恢复成功后回到已完成列。活动记录使用“某成员将任务从待办移动到进行中”一类可读文案，不直接展示原始 JSON。

## 状态与错误处理

- 搜索输入使用轻量防抖，避免每次按键立即请求。
- 筛选请求失败时保留当前任务结果、URL 和筛选控件值，并提供重试入口。
- 创建、编辑、状态更新、归档和恢复只禁用相关控件，不锁定整个页面。
- 归档、恢复或编辑失败时保留原任务状态，不做乐观假成功。
- 活动记录加载失败只在活动区显示错误和重试，不阻塞看板使用。
- 未认证请求沿用现有会话处理；非团队成员访问继续返回 403。

## Demo 数据

新增只能由开发者在本地命令行执行的 seed 脚本，不提供公开 HTTP 初始化接口，并在生产环境拒绝运行。

脚本使用固定 UUID 和固定 Demo 邮箱，在单个事务中 upsert 以下数据：

- 一个团队负责人和一个普通成员。
- 一个示例团队和项目。
- 覆盖待办、进行中、已完成、逾期、临期、未指派和已归档场景的任务。
- 与示例任务匹配的活动记录。

脚本只更新自己的固定 Demo 数据，不删除或覆盖其他用户数据。密码必须通过 `DEMO_USER_PASSWORD` 环境变量提供；仓库不保存真实密码、数据库口令或 AI Key。重复执行得到同一套 Demo 数据，不累积重复记录。

## 测试策略

### 后端

- 看板默认排除归档任务，归档视图只返回归档任务。
- 关键词、负责人、优先级和截止状态可单独及组合筛选。
- 截止状态覆盖 UTC 日期边界、已完成任务和空日期。
- 创建任务可保存截止日期。
- 仅已完成任务可归档，归档任务可恢复，重复操作返回 409。
- 非团队成员不能查询、归档或恢复任务。
- 任务变更和活动写入在同一事务中成功或回滚。
- 活动响应不包含密码哈希等敏感字段。
- seed 脚本重复执行后记录数量和固定标识保持稳定。

### 前端

- URL 查询参数可以初始化并保留组合筛选。
- 搜索防抖后发送正确查询参数，失败时保留已有看板。
- 卡片正确展示正常、临期和逾期标签，已完成任务不显示逾期。
- 创建任务传递截止日期。
- 归档确认、成功移除、失败保留和恢复回到已完成列行为正确。
- 活动区加载和错误降级不影响看板操作。
- 拆分后的 AI 任务草稿流程保持现有行为。
