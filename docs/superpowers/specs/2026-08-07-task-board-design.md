# 项目任务看板设计

## 目标

在现有团队项目页中，为每个项目提供一个可用的任务看板闭环：进入看板、读取任务、创建任务，以及在待办、进行中、已完成三种状态间迁移。

## 范围

- 项目卡片增加“进入看板”入口，路由为 `/projects/:projectId/board`。
- 看板加载 `GET /api/projects/:projectId/tasks`，按 `todo`、`in_progress`、`done` 三列渲染。
- 创建任务表单调用 `POST /api/projects/:projectId/tasks`。
- 每张任务卡片通过状态操作按钮调用 `PATCH /api/tasks/:taskId/status`。
- 请求中仅禁用对应操作；失败保留当前任务列表并展示错误提示。

## 不在本次范围

- 拖拽排序或拖拽迁移。
- 任务指派、成员管理、附件、评论和 AI 自动分配。
- 截止日期编辑、任务删除和项目编辑。
- 后端接口、数据库表或权限模型的改造。

## 数据与状态

前端定义 `TaskSummary`、`TaskStatus` 与 `TaskBoardResponse` 类型，复用后端已经返回的字段。看板页面首次挂载读取任务；创建成功后将任务加入待办列；迁移成功后仅在内存中从原列移除并加入目标列，不重新拉取整个看板。

## 错误处理

- 加载失败：显示错误和返回项目列表入口。
- 创建失败：保留输入内容并恢复创建按钮。
- 状态迁移失败：保留原列内容并恢复当前任务操作按钮。
- 路由参数缺失：显示安全错误状态，不发请求。

## 测试

- 项目列表中的入口导航到指定项目看板。
- 看板按三列展示接口返回的任务。
- 创建任务后任务出现在待办列。
- 迁移成功后任务从原列移动到目标列。
- 请求失败时展示错误且不丢失当前任务数据。
